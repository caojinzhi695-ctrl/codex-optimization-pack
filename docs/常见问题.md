# 常见问题

## 下载后就生效了吗？
不会。需要按 [安装说明](安装说明.md) 把 Skill 复制到用户技能目录，并把规则合并到有效全局指令文件，再新开会话。

## 已安装但没触发怎么办？
先检查目录是否为 .agents/skills/技能名/SKILL.md、文件是否有内容。新开会话或重启应用刷新，再明确调用 $reuse-first 或 $github-project-delivery。检查实际 CODEX_HOME 以及 AGENTS.override.md；项目规则或当前明确要求也可能改变行为。

## 一定要安装所有 MCP 吗？
不需要。优先已有检索、文件搜索和浏览器；只有现有方式不足再增加工具。依据见 [工具评估](工具评估.md)。

## 能保证省多少额度吗？
不能。检查次数、上下文、缓存、网络、任务复杂度都会影响消耗。现有验收没有同任务配置前基线，不能量化节省比例。

## GitHub 网页能打开，Git 推送失败怎么办？
浏览器和命令行可能使用不同网络路径，或只有浏览器已登录。先核实网络与 Git Credential Manager/SSH 登录；可在本次命令沿用用户已有代理，不自动改全局代理，不关 TLS 校验，不在聊天中提供密码或令牌。保留本地提交，准确区分仓库创建和文件已上传。

## 登录与权限由谁处理？
你本人完成登录、验证码和所需账号授权。没有授权时不自动购买、推送、发布或修改外部仓库；明确要求上传后，在该范围内继续。

## 可以一键覆盖旧配置吗？
不要。先备份，比较并合并规则；保留你的模型、登录、订阅和有效配置。回滚时仅移除本包的标记区块与本次安装的 Skill，保留后续修改。

## 新流程是否已有完整真实项目验收？
reuse-first 已做新项目和小改行为验收。github-project-delivery 新增后检查了格式、链接及副本一致性，尚未再运行一个完整项目作为独立行为验收；不把当前文档补全等同于所有未来项目都已验证。
