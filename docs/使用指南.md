# 使用指南

## 新项目：从需求到可用方案
说明你要解决的问题、使用设备、必需功能及预算；没有技术选型也可以开始。例如：

> 我想在 Windows 上离线整理个人笔记，必须支持中文和 Markdown，免费，能导出数据。优先成熟 GitHub 项目。

Codex 应先检查当前项目与过去的结论，再有限检索原仓库，区分“原生支持、配置支持、需二次开发、尚未确认”。给出简短选择理由后，在已授权范围内继续实施。遇到登录或权限阻塞时由你本人处理，其余工作继续。

实际采用后，项目中保存 docs/reuse-decisions.md，包括来源、许可证、固定版本、复用范围与验证结果。下一次先读记录；版本或需求变化再补查。

## 小修改：直接完成
例如“把标题改成项目名称”或“按钮文字颜色改为蓝色”。这类修改不需要重新比较 GitHub 项目，仍应核对实际改动。规则不会阻止必要的文档或接口查询。

## 上传项目：先写说明再交付
明确项目目录与目标 GitHub 仓库；已有仓库则使用原仓库。上传前应有一份你能看懂的说明：
- 这是什么，适合谁，解决什么问题。
- 需要安装什么，费用和登录前提是什么。
- 第一次怎么用，日常怎么启动或调用。
- 每个主要目录有什么，哪些功能完成、哪些没验证。
- 本次改了什么，上传哪些文件，排除哪些私人文件。

文档准备好后，在你的上传授权范围内提交并推送；目标或公开/私有选择不明时才补问。上传后给真实仓库地址、说明入口、分支和提交号。具体规范见 [项目上传流程](项目上传流程.md)。

## 继续与更新
> 继续这个仓库，只补齐这次变化相关的说明与更新记录，不重写无关文档。

配置包不是可直接运行的软件；迁移电脑需要重新安装 Skill 并合并规则。只想使用一个流程时，可以只安装对应 Skill，并只合并相关规则。
