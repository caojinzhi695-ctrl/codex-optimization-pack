# 项目上传流程

用户偏好：以后上传或更新项目到 GitHub，按完整项目交付准备说明，不只上传代码。流程本身不授权未被要求的外部发布。

1. 确定本次项目、目标账号/仓库、分支与可见性，已有明确选择不重复询问。
2. 阅读现有文档与目录，补齐中文 README：标题、用途、适用人群、功能、环境/费用、首次使用、例子、目录与限制。
3. 按项目复杂度准备安装配置、日常使用、验证结果及更新记录。可合并到 README，不为了数量生成空文档；无界面的配置包不编造应用截图。
4. 对照实际文件检查路径、链接、命令、版本及功能状态；配置包说明备份、合并和回滚。
5. 检查上传文件。排除凭据、个人配置、原始日志、无关备份、缓存和依赖；保留必要上游许可证及署名，不自动新增许可证。
6. 展示文件变化；在已有上传授权内核对 origin、fetch 和分支状态，只提交本次明确文件，不强推或覆盖无关修改。若专用技能要求预览后确认，遵从该要求。
7. 推送后核对远端分支、提交与文件，确认 README 可读；给仓库地址、说明入口及提交号。失败时说明哪部分仅在本地。
8. 以后更新只修改相关说明与更新记录，已有调查有效则继续复用，不重复完整研究。

本次仓库按以上要求补齐 README、安装/回滚、使用指南、常见问题、工具评估、验证结果及 CHANGELOG；同一流程保存为 skills/github-project-delivery/SKILL.md，供以后按需调用。
