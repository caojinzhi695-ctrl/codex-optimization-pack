# codex的优化包

给非专业开发者使用的 Codex 工作配置：**新项目先找成熟方案，上传项目先写好说明。**

它是一套 Markdown 规则与 Skill，不是独立软件。下载仓库后，需将 Skill 安装到个人目录、合并全局规则，再新开 Codex 会话。

## 适合谁，能解决什么问题

适合主要用自然语言让 Codex 做工具、网站或配置项目，希望减少从零开发、重复搜索和无效试错的人。

| 你要做什么 | 配置后的默认行为 |
| --- | --- |
| 新建工具、网站或较大功能 | 先查项目现有能力与复用记录，再有限搜索 GitHub |
| 选择成熟方案 | 通常核实最相关的 2—3 个候选，比较功能、安装、维护、费用与许可证 |
| 开始实施 | 优先直接使用、配置、少量修改，再考虑组件和从零开发 |
| 修改错别字、颜色、少量字段 | 直接处理，做必要检查，不重新长篇搜索 |
| 上传或更新项目到 GitHub | 先准备中文说明和验证记录，再核对文件、提交并验证远程内容 |

搜索不到合适方案时继续必要开发；已有调查且需求/版本未变时复用记录。不为复用强行采用复杂系统。

## 包里有什么

- **reuse-first**：先检索、再实施、保存项目复用结论。
- **github-project-delivery**：上传项目时补齐介绍、安装使用、目录说明、验证与更新记录。
- **全局规则模板**：用少量规则触发详细 Skill，避免每次加载整套流程。
- **中文说明**：安装与回滚、使用示例、常见问题、工具评估和验证记录。

## 环境与费用

已在 Windows 本地 Codex 桌面版和随附 CLI 完成部分行为验证，具体版本和范围见 [验证结果](docs/验证结果.md)。需要已登录并能正常使用的 Codex；GitHub 上传还需要目标仓库权限和可用网络。

本包不新增收费服务，也不自动购买订阅。Codex 任务仍消耗你的现有额度；第三方项目或服务的费用按实际选择核实。本包不承诺固定额度节省比例。

不修改模型、登录方式或审批权限，不包含个人 config.toml、密钥、原始备份及会话日志。

## 第一次使用：三步安装

1. 备份同名文件后，把 skills/ 中需要的 Skill 文件夹复制到用户目录的 .agents/skills/ 下。Windows 通常为 %USERPROFILE%\.agents\skills\。
2. 备份当前有效的全局指令文件，将 templates/AGENTS.md 中的规则合并进去。默认位置为 %USERPROFILE%\.codex\AGENTS.md；自定义 CODEX_HOME 或存在 AGENTS.override.md 时，按 [安装说明](docs/安装说明.md) 处理。
3. 新开本地 Codex 会话，检查规则与 Skill 是否被发现。完整安装、验证和回滚见 [安装说明](docs/安装说明.md)。

仅下载仓库不会自动安装到另一台电脑；本仓库所在电脑已经配置，并不代表下载者也已配置。

## 怎么用

直接对 Codex 描述需求即可，也可明确点名 Skill：

> 使用 $reuse-first，我想做一个 Windows 本地 Markdown 博客工具，免费、可离线生成、不需要数据库。先比较成熟方案，再在授权范围内继续配置。

> 继续这个项目，先读 docs/reuse-decisions.md，需求和版本没变就不要重新完整调查。

> 只把按钮文字颜色由 red 改为 blue，其他不变。

> 按 $github-project-delivery 把这个项目上传到我的 GitHub。先写好中文项目介绍、安装和使用方法、目录说明、验证结果与更新记录，再核对目标仓库及上传文件。

更多场景见 [使用指南](docs/使用指南.md)，遇到问题见 [常见问题](docs/常见问题.md)。

## 验证与限制

已验证：新会话收到复用规则；新项目示例先比较 Hugo/Hexo 并写记录；小修改无需网页研究；官方文档查询、浏览器和 Skill 格式检查可用。

新增项目交付流程已检查格式、文档链接和安装副本一致性；尚未对该流程另跑一个完整真实项目。规则是模型指导，不能保证每次执行完全相同。其他系统、云端环境与未来版本需重新核实。

此仓库是用户编写的配置文档，不打包上游项目源码。采用第三方项目时另核实其许可证并保留署名；本仓库未新增 LICENSE，公开可见本身不等于自动授予开源许可。
